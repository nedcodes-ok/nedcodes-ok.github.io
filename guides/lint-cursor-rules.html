How to lint your Cursor rules

Find broken frontmatter, conflicting instructions, and vague prompts before they waste your time.

Why lint rules at all?

Cursor doesn't tell you when a rule is broken. If the frontmatter is malformed, the rule silently disappears. If two rules contradict each other, Cursor picks one and ignores the other. If a glob pattern has a typo, the rule never loads for the files you intended.

You won't see an error. You'll just notice Cursor "ignoring" your instructions and wonder why.

Linting catches these problems before they cost you time. One command scans every .mdc file in your project and reports exactly what's wrong.

Quick start

Run this from your project root:

npx cursor-doctor lint

No install needed. No config. It scans .cursor/rules/ and prints warnings and errors for each file.

For a broader health check that includes a grade, token count, and summary:

npx cursor-doctor scan

What gets checked

cursor-doctor runs 100+ checks across your rule files. Here are the categories that catch the most real bugs:

Frontmatter errors

Every .mdc file needs a YAML frontmatter block between --- markers. These checks catch the structural issues that make rules silently fail.

Error

Missing YAML frontmatter

The file has no --- block at the top. Cursor may ignore the entire file.

Error

YAML parse error

The frontmatter has a syntax mistake: bad indentation, a missing colon, or an unclosed quote. The rule won't load.

Error

Rule will never load

alwaysApply: false with no globs. This rule only activates if you reference it by name, which most people never do.

Warning

Missing description

The description tells Cursor when to apply the rule. Without one, Cursor has to guess.

Glob pattern issues

Globs control which files trigger a rule. A bad glob means the rule loads for the wrong files, or never loads at all.

Warning

Overly broad glob

Patterns like * or ** match everything. If you want the rule to always apply, use alwaysApply: true instead.

Warning

Windows backslashes in glob

Glob patterns use forward slashes. src\components\*.tsx won't match anything.

Warning

Comma-separated globs

Using "*.ts, *.tsx" as a single string. This should be a YAML array with one pattern per line.

Content quality

Rules that parse correctly can still be ineffective. These checks flag instructions that waste tokens or confuse the model.

Warning

Vague instruction

Phrases like "write clean code" or "follow best practices" don't change model behavior. They just burn tokens.

Warning

Empty rule body

The file has frontmatter but no actual instructions after it.

Warning

Duplicate content

Two or more files contain nearly identical instructions. This wastes your token budget.

Cross-file checks

Some problems only appear when you look at all your rules together.

Warning

Semantic conflict

One rule says "use semicolons," another says "omit semicolons." Cursor picks one silently. The linter finds these contradictions across all your files.

Warning

Overlapping globs

Two rules target the same files with different instructions. This creates unpredictable behavior.

Reading the output

The lint command groups results by file:

.cursor/rules/typescript.mdc
  ⚠  Vague rule detected: "follow best practices"    (line 8)
  ⚠  No alwaysApply or globs set                     (line 1)

.cursor/rules/react.mdc
  ✓  No issues

.cursor/rules/testing.mdc
  ✗  YAML frontmatter error: bad indentation          (line 2)

3 files scanned · 1 error · 2 warnings

Errors (✗) are things that prevent the rule from working at all. Fix these first. Warnings (⚠) are things that reduce effectiveness or waste tokens.

The scan command

If you want the big picture instead of per-file details, use scan:

npx cursor-doctor scan

This gives you a health grade (A through F), total token count, file count, and a summary of the most important issues. Think of scan as the dashboard and lint as the detailed report.

Fix what you find

Most lint issues have straightforward fixes:

  • Missing frontmatter: Add a --- block with description and either alwaysApply: true or globs.
  • YAML errors: Check indentation. YAML is whitespace-sensitive. Use spaces, not tabs.
  • Vague instructions: Replace generic advice with specific, actionable commands. "Handle errors properly" becomes "Wrap route handlers in try-catch. Return {error, code} on failure."
  • Conflicts: Decide which rule should win and update the other. Or scope them to different files with globs.

For automated fixes, cursor-doctor Pro can fix most issues in one pass:

npx cursor-doctor fix --dry-run  # preview changes
npx cursor-doctor fix            # apply fixes

Lint in CI

You can run cursor-doctor in GitHub Actions to catch rule bugs before they merge. The check command exits with a non-zero code on D or F grades, which fails the CI step.

npx cursor-doctor check

See the full CI setup guide for a copy-paste workflow file.

VS Code extension

If you use Cursor (which is built on VS Code), you can get lint results directly in the editor. The cursor-doctor extension shows warnings inline as you edit .mdc files, with quick-fix suggestions for common issues.
